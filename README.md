# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Что прислать в бота

- Ссылку на pull request и SHA проверяемого коммита. Можно использовать свой учебный репозиторий. Сохраните начальный код первым коммитом, затем откройте PR из отдельной ветки.
- Короткую инструкцию запуска и прогона теста. В описании PR ответьте, где проверяется результат AI, что происходит при сбое, какой AI вы использовали и что проверили самостоятельно. Если работали без AI, укажите это.
- Одну фразу о том, какую пользу задача даёт менеджеру и как её можно измерить.

После сдачи бот может задать один-два коротких вопроса по вашему коду. Используйте учебные данные. Если не уложились по времени, отметьте незавершённые части в PR.

## Проверка решения

```sh
node --test triage.test.mjs
```

Тесты используют встроенный Node.js test runner, без зависимостей. Поднимают API на свободном локальном порту: проверяют HTTP-статусы, все маркеры имитатора, некорректный ввод и лимит ожидания. Отдельно проверяется fallback даже для провайдера, который игнорирует отмену, очистка старого черновика, ошибка сети и ответы в обратном порядке. UI-логика проверяется через функцию рендера; это не браузерный e2e.

Ручная проверка: запустить `node server.mjs`, открыть страницу, получить обычный черновик, затем по очереди отправить `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`. Вместо старого черновика появится ручной разбор. Пробелы не отправляются в API. Никакой ответ клиенту автоматически не отправляется.

## Решение и польза

- Ввод проверяется на сервере до вызова AI: битый JSON, отсутствие строки и пробелы дают 400 `invalid_input`.
- Ответ AI проверяется в `triage`: допустимая тема и непустой черновик после trim. Поля ответа собираются явно, неизвестные поля модели не передаются клиенту.
- Лимит AI — 300 мс: Promise.race ограничивает ожидание, AbortController отменяет поддерживающий signal провайдер; таймер очищается. Имитатор оставлен без изменений.
- При любой ошибке AI — HTTP 200 `manual_review` с null-полями, согласно контракту задания. Ошибки сети на странице также ведут к ручному разбору. Ожидание HTTP на клиенте дополнительно ограничено 5 секундами.
- Предыдущий черновик очищается при новом запуске и изменении ввода. Идентификатор запроса защищает от поздних результатов; данные выводятся через textContent.
- Менеджер получает черновик для проверки либо явный ручной сценарий, без риска принять старый ответ за новый. Пользу можно измерять временем обработки с учётом правок, долей принятых черновиков и долей ручного разбора при сохранении качества.

AI при выполнении: Codex. Использован для реализации и тестов. Проверки, фактически выполненные в среде разработки, перечислены в описании PR; ручная проверка в браузере не заявляется без её проведения.
