## Результат

Менеджер получает проверенный черновик либо понятное предложение разобрать заявку вручную. После ошибки или нового ввода старый черновик не остаётся на экране.

## Изменения

- Проверка JSON-ввода и непустой строки: HTTP 400 invalid_input.
- Проверка результата AI в server.mjs / triage: тема из allowlist, непустой строковый draft; неизвестные поля не возвращаются.
- Deadline 300 мс с отменой и fallback даже при игнорировании signal провайдером. При сбое HTTP 200 manual_review, topic/draft = null, как требует README.
- Интерфейс с понятными сообщениями, очисткой предыдущего результата, обработкой ошибок сети и защитой от устаревших ответов.
- Имитатор AI не изменялся; внешние зависимости не добавлялись.

## Проверки

Выполнены: node --test triage.test.mjs (6 тестов), node --check server.mjs, node --check client.mjs, git diff --check.
Тесты включают реальный локальный HTTP API, все пять сценариев сбоя имитатора, неверный ввод, валидные результаты, провайдера без поддержки отмены и UI-логику при смене порядка ответов/ошибок. Браузерный e2e и ручной просмотр страницы не выполнялись; инструкция ручной проверки находится в README.

## Использование AI

Задание реализовано с помощью Codex: код, тесты и документация. Проверены контракт задания, исходный diff и результаты исполнимых тестов. Ручную проверку кандидату перед отправкой следует выполнить по README, чтобы самостоятельно подтвердить поведение и разобраться в реализации.

## Польза

Меньше ручного набора без риска использовать старый или некорректный черновик. Измерение: время обработки с учётом правок, доля черновиков без исправлений и качество итоговых ответов.
